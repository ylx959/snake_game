# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Server-authoritative snake. A Python game server owns every rule and runs the
clock; the browser draws the state it is sent and forwards key presses.

## Commands

```bash
# backend
cd backend
python3 -m venv .venv                     # first time
.venv/bin/pip install -r requirements.txt
./dev.sh                                  # uvicorn --reload ; PORT=9000 to move it
.venv/bin/python main.py                  # ws://127.0.0.1:8000/ws , no reload
.venv/bin/pytest                          # everything
.venv/bin/pytest -m command               # one marker group; see below

# web
cd web
npm run dev                               # http://127.0.0.1:3000, Fast Refresh
npm run typecheck                         # tsc --noEmit
npm run lint                              # eslint . (next lint was removed in Next 16)
npm run build && npm start                # production check
```

Every pytest case carries a marker, mirroring the file it lives in:

```bash
.venv/bin/pytest -m wire                  # one group
.venv/bin/pytest -k "absent food"         # by name
```

Markers: `snake` `collision` `game` `wire` `command`, registered in
`backend/pyproject.toml`.

Both servers must be running to use the app. The game server binds **loopback
only**, so use `127.0.0.1`, not `localhost` — on macOS `localhost` may resolve
to `::1` first and fail.

## Environment notes

- **Do not remove `allowedDevOrigins` from `web/next.config.ts`.** `next dev`
  rejects dev-only endpoints — including the HMR WebSocket — for any request
  carrying an Origin it was not started with, and browsers always send Origin.
  Without that setting the HMR upgrade returns 400, the dev client never finishes
  booting, and every page renders from SSR but **never hydrates**: effects never
  run, the board stays blank, the status sticks on "connecting", and there is no
  console or build error of any kind. It reproduces on a trivial page and under
  both Turbopack and `--webpack`, so it looks like broken app code and is not.
- `devIndicators: false` is in the same file because the board is full-bleed and
  `next dev`'s floating badge sits on top of the game. Compile and runtime
  errors still surface.
- `web/AGENTS.md` and `web/CLAUDE.md` are regenerated by `next dev` and are
  gitignored. They are not hand-written project docs.
- `education.md` is a hand-written teaching guide (in Chinese) that cites this
  code as `path:line` throughout, and its exercises assert specific outcomes —
  "change this line, this named test fails". **Moving code silently rots it**,
  and nothing checks the references. If you shift line numbers in
  `backend/game/` or `web/lib/`, re-check the citations; if you change a rule,
  re-check the chapter that teaches it. It also deliberately keeps C++/Python
  comparisons from the backend rewrite — those are teaching material, not stale
  text to clean up.

## Architecture

### The wire contract is written twice

`Game.to_dict()` in `backend/game/game.py` and `web/types/game.ts` describe the
same message. **Change both in the same commit.** There is no schema and no
codegen. The `wire` tests pin the serialized shape on the Python side — they
assert the exact key set, so a field renamed or dropped there fails — but
nothing checks that `types/game.ts` agrees, so a field added on one side alone
still slips through.

The server pushes `{"type":"state", ...}` every tick; the client sends
`{"type":"turn"|"start"|"pause"|"reset"|"resize"}`. The client never computes
game state.

### Why the split matters

The server runs the clock, so a client cannot move faster by sending more
messages, and every rule is testable without a socket. If you find yourself
adding game logic to the browser, it belongs in `game.py`/`snake.py`/
`collision.py`.

Two places bend that rule, both deliberately:

- **Colour.** The server sends `palette`, an integer index that advances by one
  with every apple. The hex values live in `web/lib/palette.ts`. The *decision*
  stays on the server; only the appearance is the client's, so a colour can be
  retuned without restarting the backend or dropping a player's run.
- **Board size.** The board fills the viewport, so its shape is the one piece of
  game state only the browser knows. It measures (`web/lib/board.ts`), sends
  `{"type":"resize", "width":…, "height":…}`, and the server clamps it to
  `MIN_DIMENSION..MAX_DIMENSION` and calls `reset()`. Resizing therefore ends
  the current run — the client only sends a size that actually changed, and
  debounces window drags, so this bites only on a real resize.

### backend

FastAPI + uvicorn, three dependencies pinned in `requirements.txt`. There is no
packaging step; `tests/conftest.py` puts the backend root on `sys.path`.

- `main.py` is wiring only: one `Game` per connection, an asyncio task pushing
  state at the tick rate, and the receive loop pumping commands. **There is no
  lock.** Everything is on one event loop, so the ticker and the command pump
  cannot observe a half-updated `Game`; cancelling the task ends the clock at
  once rather than one tick later.
- `command.py` owns the client half of the protocol. `parse_command()` is a pure
  function from text to a value, tested without a `Game`, a socket, or an event
  loop; `apply()` is the only part with a side effect. Parsing never raises —
  malformed text off a socket is an expected case, so every rejection is
  `None`. Note the `bool`-is-an-`int` guard on `resize` dimensions.
- `collision.py` is pure predicates over a *candidate* cell and a body, which is
  what lets `Game` ask "would this kill me?" before moving anything.

Three rules in `game.py`/`snake.py` are load-bearing and easy to break:

- `Game.tick()` checks `is_fatal(snake.next_head(), ...)` **before** moving, and
  returns without moving on death. The snake stops at the edge; it never steps
  off the board.
- Food is resolved **before** `snake.move()`. That is what makes growth and score
  land on the same tick, and it keeps the tail in place so the new segment
  appears immediately.
- `hits_self()` excludes the last body cell, and `Snake.turn()` compares against
  the *committed* `_direction` while buffering into `_pending`. The first makes
  following your own tail legal; the second is what stops two key presses inside
  one tick folding the snake onto its own neck (UP is legal from RIGHT, LEFT is
  legal from UP).

### web

Layered so that only one file knows about both React and the socket:

- `lib/` (`websocket.ts`, `input.ts`, `renderer.ts`, `palette.ts`, `board.ts`)
  imports no React. `Renderer` is stateless with respect to the game — it draws
  exactly the state it is handed, so it cannot disagree with the server.
- `hooks/useSnakeGame.ts` is the only React↔socket seam: socket lifecycle,
  server state mirrored into React state, keyboard binding, and the `resize`
  push. That push runs on every fresh connection, because a reconnect gets a new
  `Game` back on the default board.
- `components/game/` is presentational. `ScoreBoard` and `Prompt` show
  connection status instead of game status while the socket is not open, because
  that is the thing the player can act on.

The board is the page. The canvas is `position: fixed; inset: 0`, and the
readouts and controls float on top of it with `pointer-events: none` except on
the buttons — so the snake runs behind the text.

Two rendering details are load-bearing:

- The board fills the viewport exactly, so cell sizes are fractional and very
  slightly non-square. `Renderer.bounds()` rounds every cell edge to a whole
  pixel, and neighbours round the shared edge to the same integer — that is what
  keeps squares hard-edged with no seam between them.
- `GameCanvas` resizes the canvas only when the window or the board actually
  changed, never on a tick: resizing reallocates the backing store and wipes it.

`lib/input.ts` skips **only Space** when a button has focus, because a focused
button answers Space itself and would otherwise pause and resume in one
keystroke. Do not widen that to all keys — an earlier version did, and clicking
Start left the arrow keys dead.

The `@/*` path alias maps to the **web root**, not `src/` — there is no `src/`.

The backend URL comes from `NEXT_PUBLIC_WS_URL` (`web/.env.local`), falling back
to `ws://127.0.0.1:8000/ws`.
